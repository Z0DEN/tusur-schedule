# Объединённый вид: пары + план задач + личные события

## 1. Принятое решение (2026-11-17)

Пары и личные события живут в **Google Calendar**; агент читает занятое время,
подгоняет под него план и пишет задачи в **Vikunja**. Календарь — вход для
планирования, Vikunja — место плана. Проекция плана обратно в календарь сейчас
**не делается** (варианты — в приложении А).

| Слой | Где живёт | Кто пишет |
|---|---|---|
| Пары | Google Calendar, подписка на публичный `schedule-735-1.ics` | GitHub Actions через Pages |
| Личные события | Google Calendar, свои календари | пользователь |
| План работ | **Vikunja** (задача-блок с `start_date`/`due_date`) | агент через `plan_apply` |

Google — источник занятого времени, Vikunja — источник плана. Между ними одна
стрелка: Google → планировщик. Обратной записи нет, поэтому и конфликта двух
систем нет.

## 2. Откуда берётся занятое время

1. **Пары** — из своего источника (кэш / `schedule-735-1.ics`), а **не** из
   Google: подписка Google обновляется раз в 8–24 часа, и пара, перенесённая
   сегодня, доедет до Google к вечеру.
2. **Личные события** — из Google по секретному iCal-адресу (только чтение).
   `RRULE` разворачивается на горизонт 14 дней, `EXDATE` учитывается,
   `RECURRENCE-ID` — как замена вхождения.
3. **Дублей нет**: события из Google-копии нашего фида отбрасываются по `UID` с
   суффиксом `@timetable.tusur.ru`. Если Google переписывает UID подписки —
   сравниваем `DTSTART/DTEND/SUMMARY` с допуском 1 минута.

## 3. Ежедневный прогон

```
1. пары на 14 дней (свежие) + личные события Google (iCal)
2. свободные окна = 10:00–00:00 минус пары минус личное минус буферы
   (10 мин УЛК→УЛК, 25–30 мин до физкультуры, 30 мин перед парой без аудитории)
3. Vikunja: задачи, изменённые с прошлого прогона (`updated > курсор`)
4. новые задания без оценки → агент ставит метку est-* и разбивает на шаги
5. агент обогащает задачи через Vikunja MCP, затем plan_check → plan_apply
6. запись в Vikunja: задача-блок с `start_date` и `due_date`
7. diff.json (локально): что изменилось и почему
```

## 4. Как это выглядит на экране

Google Calendar — занятое время:

```
пн 24.11
  12:15–13:45  ТВиМС, УЛК 310
  14:00–15:30  Физика, УЛК 408
  18:00–19:00  врач                    ← личное, из Google
```

Vikunja (Gantt) или Tasks.org — план:

```
19:20–20:20  ЧМ: решить пункты 1–2    est-3h, срок 06.12
20:30–21:30  ЧМ: оформить и сдать     est-3h, срок 06.12
```

Свободные окна, из которых выбраны слоты: `10:00–12:05`, `15:40–17:50`,
`19:20–00:00`. План не встаёт на пару, на личное событие и не подходит к сроку
ближе 24 часов (при нехватке окон — не ближе 6 часов, с меткой `горит`).

## 5. Задержки, которые надо знать

| Что | Задержка |
|---|---|
| Пары в планировщике | минуты (свой источник) |
| Пары **на экране** Google | 8–24 ч — подписка Google обновляется медленно |
| Личные события для планировщика | 5 мин – несколько часов (кэш Google) |
| Реакция плана на новую задачу | 5–10 мин (опрос) или мгновенно (если заработает вебхук) |

## 6. Что нужно от пользователя

1. Секретный iCal-адрес личного календаря (или нескольких) — только чтение.
   **Статус: не получен.**
2. Решить, считать ли события «на весь день» занятыми (день рождения и поездка —
   разные вещи).
3. Когда включим Pages — добавить подписку на `schedule-735-1.ics` в Google.

## 7. Цена

Один прогон агента в сутки ~0.5–1.5 ₽ (Vikunja MCP + наш `tusur` в контексте);
пересборка по изменениям без новой текстовой задачи — код, 0 ₽.

## Приложение А. Рассмотрено и отклонено

Проекция плана в календарь (чтобы блоки стояли рядом с парами) не нужна сейчас,
но возможна позже без переделки остального: Vikunja остаётся источником истины.

| # | Способ | Без ноутбука | Сложность | Почему не сейчас |
|---|---|---|---|---|
| 1 | Google CalDAV + пароль приложения: `PUT` `VEVENT` в календарь «Учёба: план» | да | средняя | нужен пароль приложения (2FA) и проверка, что Google принимает запись |
| 2 | Service account в Google Cloud, календарь расшарен на его email | да | выше | проект в Cloud и ключ ради косметики |
| 3 | Приватный `.ics` на Tailscale (`:8787/plan-735-1.ics`) | **нет** | низкая | ноутбук должен быть включён |
| 4 | Всё в Vikunja через CalDAV (`VTODO`) | да | низкая | задача со сроком — маркер, а не полоса 19:00–20:30 |

Отдельно проверено: сетки-календаря в Vikunja нет (`list`, `gantt`, `table`,
`kanban`), `VEVENT` она не понимает — см. `vikunja-integration.md` §7.

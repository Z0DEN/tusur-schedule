# Объединённый вид: пары + план задач + личные события

Цель пользователя (2026-11-17): видеть в одном месте три слоя — расписание пар,
план работ по заданиям и личные события.

**Решение (2026-11-17):** пары и личные события остаются в **Google Calendar**;
агент читает занятое время из Google, подгоняет под него план и пишет задачи в
**Vikunja**. Календарь — вход для планирования, Vikunja — место плана. Разбор
отвергнутых вариантов доставки блока в календарь — §5.

## Модель: три слоя, один календарь-клиент

Календарные приложения умеют накладывать несколько календарей друг на друга с
разными цветами и переключателями видимости. Поэтому «объединить» = сделать так,
чтобы все три источника были **календарями в одном приложении**, а не сваливать
их в одну базу.

| Слой | Источник истины | Куда попадает | Приватность |
|---|---|---|---|
| Пары | `timetable.tusur.ru` | публичный `schedule-735-1.ics` (GitHub Pages) | публично, там нет ничего личного |
| План задач | Vikunja (задачи, оценки, шаги) | **проекция**: блоки как `VEVENT` | приватно — в названии блока стоит задание |
| Личные события | Google Calendar | уже там, ничего переносить не надо | приватно |

Ключевое правило: **Vikunja остаётся источником истины**, календарь — только
проекция в одну сторону. Двигаешь блок в календаре — планировщик об этом не
узнает; двигать надо в Vikunja/Tasks.org. Иначе получаем двусторонний конфликт
из двух систем, который никто не выиграет.

## Четыре способа доставить слой плана

| # | Способ | Без ноутбука | Приватность | Сложность | Что проверить |
|---|---|---|---|---|---|
| 1 | **Google CalDAV + пароль приложения**: `PUT` `VEVENT` в отдельный календарь «Учёба: план» | да | приватно | средняя | принимает ли Google запись по CalDAV (чтение точно работает); нужен пароль приложения, то есть 2FA в аккаунте Google |
| 2 | **Service account в Google Cloud**: JSON-ключ, календарь расшарен на его email | да | приватно | выше: проект в Cloud, ключ | ничего неизвестного, но больше шагов настройки |
| 3 | **Приватный `.ics` на Tailscale-сервере** (`http://100.121.145.104:8787/plan-735-1.ics`) | **нет** — ноутбук должен быть включён и в сети | приватно (только внутри Tailscale) | низкая: генератор есть | доступность телефона к серверу в нужный момент |
| 4 | **Всё в Vikunja через CalDAV** (VTODO вместо VEVENT) | да | приватно | низкая | умеет ли твоё приложение рисовать VTODO на сетке — сетку обычно не рисуют, задачи уезжают в отдельный список |

Вариант 4 не даёт «блоков времени»: задача с `due_date` в 20:30 — это маркер, а
не полоса 19:00–20:30. Для плана нужны именно интервалы, поэтому 1–3.

Рекомендация: **№1**, с откатом на **№2**, если Google не примет запись по
CalDAV. Оба варианта дают нативное отображение на телефоне, работают без
включённого ноутбука и не требуют публиковать названия заданий. №3 оставить как
аварийный путь, если с Google что-то не сложится.

## Как это выглядит в итоге

```
Телефон, приложение-календарь
├─ [календарь 1] ТУСУР: пары        — подписка на публичный .ics
├─ [календарь 2] Учёба: план работ  — блоки из Vikunja (проекция)
└─ [календарь 3] Личное             — Google
```

Три цвета, три переключателя, один экран. Напоминания — на уровне приложения, а
не Vikunja, чтобы не приходило по два.

## Что блокирует

1. `PUT` в Google CalDAV — не проверено. Проверяется одной командой с паролем
   приложения после того, как пользователь его создаст.
2. 2FA в аккаунте Google — без неё пароль приложения не выдаётся (вариант 1
   отпадает, остаётся 2 или 3).
3. Секретный iCal-адрес личного календаря (для чтения занятых вечеров) —
   пользователь пока не дал; не блокирует проекцию, но блокирует учёт личных
   встреч при планировании.

## 8. Как работает принятый вариант

### Слои

| Слой | Где живёт | Кто пишет |
|---|---|---|
| Пары | Google Calendar, подписка на наш публичный `schedule-735-1.ics` | GitHub Actions через Pages |
| Личные события | Google Calendar, свои календари | пользователь |
| План работ | **Vikunja** (задачи с `start_date`/`due_date` = границы блока) | агент |

Google — **источник занятого времени**, Vikunja — **источник плана**. Между ними
одна стрелка: Google → планировщик.

### Откуда берётся занятое время

1. **Пары** — из своего источника (кэш/`schedule-735-1.ics`), а **не** из Google:
   подписка Google обновляется раз в 8–24 часа, и пара, перенесённая сегодня,
   доедет до Google к вечеру. Планировщик должен считать по свежим данным.
2. **Личные события** — из Google по секретному iCal-адресу (только чтение).
3. **Дублей нет**: события, пришедшие из Google-копии нашего фида, отбрасываются
   по `UID` с суффиксом `@timetable.tusur.ru` — свои же UID мы и генерируем.

### Ежедневный прогон (утром и по изменениям)

```
1. пары на 14 дней (свежие) + личные события Google (iCal)
2. свободные окна = 10:00–00:00 минус пары минус личное минус буферы
   (10 мин УЛК→УЛК, 25–30 мин до физкультуры, 30 мин перед парой без аудитории)
3. Vikunja: задачи, изменённые с прошлого прогона (`updated > курсор`)
4. новые задания без оценки → агент ставит метку est-* и разбивает на шаги
5. агент раскладывает блоки; валидатор проверяет (окно, 24 ч до срока,
   ≤3 ч предмета в день, ≤60 % загрузки, воскресенье без новых блоков,
   churn ≤3, pinned не тронуты)
6. запись в Vikunja: задача-блок с `start_date` и `due_date`
7. diff.json: что изменилось и почему
```

### Как это выглядит на экране

Google Calendar — занятое время:

```
пн 24.11
  12:15–13:45  ТВиМС, УЛК 310
  14:00–15:30  Физика, УЛК 408
  18:00–19:00  врач                    ← личное, из Google
```

Vikunja (Gantt) или Tasks.org — план:

```
19:20–20:20  ЧМ: решить пункты 1–2    est-3h, срок 06.12
20:30–21:30  ЧМ: оформить и сдать     est-3h, срок 06.12
```

Свободные окна, из которых выбраны слоты: `10:00–12:05`, `15:40–17:50`,
`19:20–00:00`. План никогда не встаёт на пару, на врача и не подходит к сроку
ближе 24 часов.

### Задержки, которые надо знать

| Что | Задержка |
|---|---|
| Пары в Vikunja/планировщике | минуты (свой источник) |
| Пары **на экране** Google | 8–24 ч — подписка Google обновляется медленно |
| Личные события для планировщика | 5 мин – несколько часов (кэш Google) |
| Реакция плана на новую задачу | 5–10 мин (опрос) или мгновенно (если заработает вебхук) |

### Что нужно от пользователя

1. Секретный iCal-адрес личного календаря (или нескольких) — только чтение.
2. Решить, считать ли события «на весь день» занятыми (день рождения или
   поездка — разные вещи).
3. Когда включим Pages — добавить подписку на `schedule-735-1.ics` в Google.

### Цена вопроса

Один прогон агента в сутки ~0.3–1 ₽; пересборка по изменениям без новой текстовой
задачи — код, 0 ₽.
